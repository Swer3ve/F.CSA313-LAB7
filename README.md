## Дүгнэлт (Хэсэг E)

Хамгийн үр дүнтэй аялал Couch Potato байсан: хоосон, хязгаарын болон давхардсан оролтоор BUG-02, 05, 06, 07, 11-ийг олсон. Saboteur аялал curl-ээр BUG-01-ийг (буруу JSON-д 400 биш 200 OK) олсон бөгөөд үүнийг UI-аар хэзээ ч олохгүй байсан. Charter-аас гадуур, хүснэгт, мессеж, тоолуур, товчны өнгө, линкийг спецификацтай харьцуулах явцад BUG-03, 04, 08, 09, 10 санамсаргүй олдсон. Эдгээр нь оролтоор довтолсны биш, дэлгэц дээр харагдсаныг спецификацтай тулгасны үр дүн байв. Шалгагдаагүй үлдсэн зүйл: HTML болон тусгай тэмдэгт оруулах, Enter товчоор нэмэх, байхгүй id-тай DELETE болон бусад HTTP метод (PUT, PATCH), гар утасны өргөн, хуудсыг дахин ачаалах. Дараагийн session-ий charter нь «API түвшний хүсэлтүүдээр (DELETE, PUT, буруу Content-Type, тусгай тэмдэгт) өгөгдлийн бүрэн бүтэн байдлыг судлах» байж болно. Playwright автомат тестээр BUG-01, 02, 03, 04, 05, 06, 07, 08, 10 баригдах байсан, учир нь эдгээр нь статус код, текст, мөрийн тоо гэх мэт тодорхой assertion-ээр шалгагдана. Гэхдээ тест бичигч эдгээр дүрмийг урьдчилан assertion болгон зохиосон байх ёстой. BUG-09 (товчны өнгө) болон BUG-11 (урт оролтод хүснэгт эвдрэх) нь харагдацын согог тул CSS эсвэл layout-ын assertion, скриншот харьцуулалтгүйгээр автомат тестээр алдагдах бөгөөд хүний нүдээр хамгийн хурдан олдсон. Дүгнэж хэлбэл, exploratory session нь дүрмийг шууд тулгаж шалгахад үр дүнтэй, харин олдсон согогийг дараа нь автомат тест болгон тогтоох нь зүйтэй.
